# Accessibility Requirements

> **Project**: 数一游园 (Shuyi Playland)
> **Target Tier**: WCAG 2.1 AA
> **Platform**: Android 竖屏 720×1280，纯触控
> **Audience**: 小学生（6–12岁）
> **Last Updated**: 2026-05-20
> **Status**: Approved

---

## Tier Commitment

本项目承诺满足 **WCAG 2.1 AA** 级别的无障碍标准，适用于所有已实现的屏幕和交互。

> **注意**：完整的 WCAG 合规验证需要配合辅助技术（如 Android TalkBack）进行手动测试和专业无障碍审查。本文档定义设计和实现的目标约束，不等同于已通过合规认证。

---

## 1. 触控目标尺寸

**要求**：所有可交互元素的最小触控区域为 **48×48 dp**。

| 元素类型 | 最小触控区 | 实现方式 |
|---------|-----------|---------|
| 底部导航 tab 按钮 | 56×56 dp | 按钮高度含图标+文字 |
| 题目选项按钮（P-03） | 48×48 dp | `minimum_size` 设置 |
| 返回/关闭图标按钮 | 48×48 dp | 透明 padding 扩大触控区 |
| 领取奖励按钮（P-07） | 48×48 dp | 按钮高度约束 |
| LineEdit 输入框（P-04） | 48 dp 高 | 输入框最小高度 |

相邻可交互元素间距 ≥ **8 dp**，防止误触。

---

## 2. 文字对比度

**要求**：正文文字与背景的对比度 ≥ **4.5:1**（WCAG AA 标准）；大文字（≥18pt 或 ≥14pt 粗体）≥ **3:1**。

| 文字类型 | 最小对比度 | 备注 |
|---------|-----------|------|
| 正文、题目文字 | 4.5:1 | 深色文字 on 浅色背景 |
| 按钮标签 | 4.5:1 | 含禁用状态（禁用时可降至 3:1） |
| 标题（大字） | 3:1 | ≥18pt 或 ≥14pt 粗体 |
| 占位文案（P-10） | 3:1 | 次要信息，允许较低对比度 |

---

## 3. 颜色不作为唯一信息载体

**要求**：不能仅靠颜色区分状态或传递信息，必须同时提供文字、图标或形状等辅助标识。

| 场景 | 颜色 | 辅助标识 |
|------|------|---------|
| 答题正确/错误 | 绿色/红色 | 同时显示"✓"/"✗"图标或文字 |
| 任务已完成/未完成 | 颜色变化 | 同时显示"已完成"文字或勾选图标 |
| 成就已解锁/未解锁 | 颜色变化 | 同时显示锁图标或"已解锁"文字 |
| 底部 tab 激活状态 | 颜色高亮 | 同时加粗或改变图标形态 |

---

## 4. 文字可读性

**要求**：正文最小字号 **14sp**；题目文字最小 **16sp**；标题最小 **18sp**。

| 文字类型 | 最小字号 | 备注 |
|---------|---------|------|
| 题目文字 | 16sp | 核心内容，需清晰可读 |
| 选项按钮文字 | 14sp | |
| 正文/说明文字 | 14sp | |
| 标题 | 18sp | |
| 次要说明（占位文案等） | 12sp | 允许较小，但不低于 12sp |

字体使用系统默认字体或已验证的中文字体，不使用装饰性字体作为正文。

---

## 5. 焦点与导航顺序

**要求**：所有可交互元素可通过逻辑顺序访问（从上到下、从左到右）。

- 底部导航 tab 顺序：Home → Practice → Growth → MiniGame → Settings
- 题目选项按钮顺序：按屏幕布局从上到下、从左到右
- 表单输入顺序：题目文字 → 输入框/选项 → 提交按钮
- 返回按钮始终可访问，不被其他元素遮挡

---

## 6. 错误与状态反馈

**要求**：操作结果必须通过视觉（文字或图标）明确反馈，不能仅依赖音效。

| 场景 | 视觉反馈 | 音效（可选） |
|------|---------|------------|
| 答题提交 | 进入下一题或显示结算 | P-06 音效（可关闭） |
| 领取奖励成功 | 按钮状态变为"已领取" | 可选音效 |
| 签到成功 | 显示奖励信息 | 可选音效 |
| 签到失败（今日已签） | 显示错误文案 | 无 |
| 空状态（P-10） | 显示占位文案 | 无 |

---

## 7. 屏幕阅读器（TalkBack）

**当前承诺**：MVP 阶段不强制要求完整 TalkBack 支持，但需满足以下基础要求：

- 所有按钮和交互元素有有意义的 `tooltip_text` 或节点名称（Godot 的 `hint_tooltip`）
- 图标按钮（无文字标签）必须有描述性 tooltip
- 不主动阻断 TalkBack 的焦点遍历

> TalkBack 完整支持（包括自定义朗读顺序、动态内容播报）列为 v1.1 功能，不在 MVP 范围内。

---

## 8. 不在 MVP 范围内的无障碍功能

以下功能已评估，决定推迟至 v1.1 或更后版本：

| 功能 | 原因 | 计划版本 |
|------|------|---------|
| 色盲模式 | 开发成本高，目标用户群体需求不明确 | v1.1 |
| 减少动画模式 | MVP 动画量少，影响有限 | v1.1 |
| 字体大小调节 | 需要全局布局适配，成本高 | v1.1 |
| 完整 TalkBack 支持 | 需要专项开发和测试 | v1.1 |

---

## 9. 验收标准

以下标准在每次 sprint 结束时通过手动测试验证：

- [ ] 所有可交互元素触控区域 ≥ 48×48 dp（用 Android 开发者选项"显示触控区域"验证）
- [ ] 正文文字与背景对比度 ≥ 4.5:1（用对比度检测工具验证）
- [ ] 答题正确/错误状态通过图标或文字标识，不仅依赖颜色
- [ ] 所有按钮标签在禁用状态下仍可读（对比度 ≥ 3:1）
- [ ] 题目文字字号 ≥ 16sp，正文 ≥ 14sp
- [ ] 空状态（错题本为空、成就未解锁）显示有意义的占位文案
- [ ] 图标按钮有 tooltip 描述（不依赖图标形状传递唯一信息）
